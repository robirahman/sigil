Sigil API

An HTTP API for programs: read players, games, the daily puzzle and the leaderboards, and connect an engine as a bot that plays on the site. Everything is JSON. Every endpoint below starts at

https://us-central1-sigil-js.cloudfunctions.net/api
BasicsTokensPublic dataBotsTurn formatErrorsSign-in

Basics

  • Requests are GET or POST (with a JSON body); answers are JSON, with Content-Type: application/json.
  • CORS is open to any origin: a web page can call the API directly. There are no cookies; a caller is known only by its token.
  • Public data needs no token. A token raises your rate limit and is needed for the bot API.
  • Everything the API reads is already public on the site. It never answers anything private: no e-mail addresses, no settings, and not the moves of games against the site's AI, which stay private to the player.

Rate limits

CallerLimit
No token60 requests a minute per IP address
With a token300 requests a minute per token
Event streams20 opened a minute per token; at most 8 open at once
Bot challenges10 a minute; at most 5 waiting at once
Bot turns120 a minute per token, across all its games

Every answer carries X-RateLimit-Limit, X-RateLimit-Remaining and X-RateLimit-Reset (Unix seconds). Over the limit you get 429 with Retry-After (seconds).

Tokens

Make a personal API token on your account page (an account with a sign-in, not a guest). The token is shown once: the site keeps only a hash of it, so it cannot show it again. Revoke it there if it leaks; deleting your account revokes all of them. You may have 10.

Send it in the Authorization header:

curl -H "Authorization: Bearer sgl_…" https://us-central1-sigil-js.cloudfunctions.net/api/v1/account
ScopeLets the token
readRead the public endpoints at the token's rate limit.
botPlay as the account through the bot API. Only a BOT account can make one.

GET /v1/account answers who the token belongs to: { uid, name, isBot, scopes, token } (token is the token's id, not the token).

Public data

EndpointAnswers
GET /v1/users/{uid}A player's profile: name, rating (elo, games, wins, losses, provisional under 10 games), puzzle rating, best Puzzle Storm score, isBot, isAI.
GET /v1/users/by-name/{name}The same, by display name.
GET /v1/users/{uid}/gamesTheir finished games, newest first: ?limit= (up to 50), ?before= (a timestamp: the next of the previous page), ?moves=1 for each online game's moves and positions (up to 10 games).
GET /v1/games/{room}A game by its room code: players, result, clock, and every turn with the position (SFN) after it. Long-poll a game in play with ?after=N&wait=S: the answer comes when it has more than N turns, or after S seconds (up to 30).
GET /v1/puzzles/dailyToday's puzzle (UTC), the one on the puzzles page. ?date=YYYY-MM-DD for an earlier day, ?solutions=1 to include the solutions.
GET /v1/leaderboard?board=rating (default), puzzles, storm or bots; ?limit= up to 100.

A game in play whose players turned spectators off is not shown until it ends.

Bots

				
A bot is an engine that plays on the site under a BOT account, like a bot on Lichess.

				
    
					
  • Making one. Make a new account, then on its account page choose Make this a BOT account. Only an account that has never played a game can become a bot, and it cannot be undone. Then make a token with the Bot play scope there.
    • 
					
  • Tagged. A bot carries a BOT tag wherever its name is shown.
    • 
					
  • Through the API only. A BOT account cannot play from the site's pages: the database refuses its moves, seats, lobby entries and challenges. Its moves reach a game only through this API, which checks each one against the game's rules first, with the same replay the site's rating uses.
    • 
					
  • Ratings. Bots are ranked on their own bots' leaderboard, never the players'. Two bots play rated when the challenger asks. A game against a human is rated only when the human chose Rated in their own challenge to the bot; a bot's challenge to a human is always casual. A bot is never rated against the site's AI.
    • 
					
  • Timed games only. Real-time or correspondence: a bot that stops answering loses on time.
    • 
				

				
Endpoints

				
All need a token with the bot scope.

				

					
EndpointDoes

					
GET /v1/bot/eventsAn event stream (Server-Sent Events) of your challenges and games: challenge, challengeCanceled, gameStart, gameFinish. Open challenges and games in play come first.

					
GET /v1/bot/games/{room}/streamOne game's stream: gameFull (as GET /v1/games/{room}, plus you, your colour), then gameState after every turn and at the end: { status, moves, sfn, toMove, clock, winner, endReason }.

					
POST /v1/bot/games/{room}/turnPlay your turn: { "actions": ["a2", "pass"] } (see the turn format). Answers { ok, turn, sfn, gameOver, winner }.

					
POST /v1/bot/games/{room}/resignResign.

					
POST /v1/bot/games/{room}/abortAbort, before both sides have moved.

					
POST /v1/bot/challenges/{room}/acceptAccept a challenge (you take the open seat and the game starts).

					
POST /v1/bot/challenges/{room}/declineDecline one, or withdraw your own.

					
POST /v1/bot/challenge/{user}Challenge a player (uid or display name): { "timeControl": { "type": "realtime", "initialTime": 300000, "increment": 3000 }, "variant": "standard", "color": "random", "rated": true }. Correspondence: { "type": "correspondence", "moveTimeout": 86400000 }. Times are in ms. Answers { room, color, rated, url }.

				

				
A stream sends a : ping comment every 20 seconds, and ends after about 9 minutes with a reconnect event: open it again. If you cannot hold a stream open, poll GET /v1/games/{room}?after=N&wait=25 instead.

A reference bot

				
tools/sigil-bot.js (Node 22, no dependencies) plays random legal turns. Start from it: replace its randomTurn() with your engine's choice.

				
node tools/sigil-bot.js --token sgl_… --accept all
node tools/sigil-bot.js --token sgl_… --challenge OtherBot --tc 5+3 --rated --games 1

			


			

				
Turn format

				
A turn is the list of clicks a player makes on the site, in order: the same tokens the site's own pages send to each other in an online game. Each answers what the game asks next:

				
    
					
  • a node name (a1 … c13): the move, a stone to sacrifice, a stone to keep after a cast, a spell's target, where to push a stone;
    • 
					
  • a spell name, as in the game's spellNames (Fireblast, Seal_of_Spring): cast it;
    • 
					
  • dash, pass (end the turn), skip_providence, submit (Rock Slide).
    • 
				

				
Examples: ["a2", "pass"] (move to a2, end the turn); ["b4", "dash", "a1", "a3", "b5", "pass"] (move, dash sacrificing a1 and a3, dash-move to b5); ["c7", "Fireblast", "c2", "pass"] (move, cast, its target).

				
The server plays the turn with the site's rules engine and refuses it unless the game takes every token and the turn ends exactly at the last one. The engine is in the site's source: docs/static/scripts/engine/ (game-controller.js asks the questions). The easiest way to make legal turns is to drive that controller yourself, as the reference bot does.

			


			

				
Errors

				
An error answers with a status code and { "error": code, "message": text }.

				

					
StatusCodes

					
400bad-request, bad-actions (a token that is not one), illegal-turn (the rules refuse the turn; the message says why), untimed

					
401unauthenticated: no token, or one revoked or never made

					
403missing-scope, not-a-bot, not-your-game, not-your-challenge, blocked, private-game

					
404not-found

					
409not-your-turn, not-playing, conflict (the game moved on: read it again), not-waiting, too-late

					
429rate-limited, too-many-streams, too-many-challenges

				

			


			

				
Signing in to other apps

				
"Sign in with Sigil" for other apps (OAuth) is not available yet. Until it is, an app can ask its users for a read token, which shows nothing that is not public.
