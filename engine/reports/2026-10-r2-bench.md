# Round 2: human-game benchmarks re-scored for v25, and the release table (2026-10-07)

Branch `r2-bench`. Run 20261007T003058Z (one Spot c3d-highcpu-90, us-east4-a,
`runner_surprise.sh` MODE=r2bench). Raw results: `2026-10-r2-bench-old-targets.json`,
`2026-10-r2-bench-v25-targets.json`. Suite provenance: `ai/data/benchmarks/README.md`.

## Why

The Step 1 surprise suite's depth-6 targets were scored by the September `tfit` engine (284
cases) and v23 (33). The sees-rate counts a case as seen when the searched value lands within
0.5 stones of that target, so an engine with a different eval is judged against another
eval's number. The Step 5 report flagged this.

## Re-scoring (`engine/harness/bench_rescore.py`)

Every case, scored with the shipped v25 search (`nnue_spell`, generator policy at width
budget >= 96, set explicitly because it is thread-local and off by default in Python), with
surprise_audit.py's definitions: target = depth-6 value of the position the reply produced;
v4 = depth-4 value of the position before it; both from the AI's side.

* 317 of 317 cases got a new target. Mean target shift -0.30 stones (median 0.00); mean
  |shift| 1.43. The depth-4 value before the reply fell by 2.75 stones on average: v25 at
  depth 4 already expects most of these replies.
* **211 of 317 are still confirmed** under v25 (v25's own depth-4 value minus its depth-6
  target > 1.0): 194 of the 284 September cases, 17 of the 33 v23 cases. By kind:
  move-only 67/93, cast 57/67, dash+cast 58/95, dash 26/53.
* Frozen as `ai/data/benchmarks/surprise_cases_v25.json`, all 317 cases with the new
  targets (`confirmed_v25` per case). Not cut to the 211, because that subset is defined by
  v25's own depth-4 miss and would bias a sees-rate against v25. `surprise_cases.json` is
  unchanged.

## Release table

Configs: v23 = `tfit`, policy off; v24 = `tfit_spell_v2`, policy off; v25 = `nnue_spell`,
`set_policy(True, 96)`. All at `DEFAULT_WIDTH_SCALE` and `SHIPPED_ADAPTIVE`. Fixed node
budgets 50k / 300k / 1.5M (about depth 4 / 5 / 6). Coverage for v25 is measured in the
policy stream the v25 search expands.

| metric | v23 | v24 | v25 |
|---|---|---|---|
| Human-find coverage, first 10 / 24 / 96 / 500 (120) | 18.3 / 24.2 / 34.2 / 45.8% | same | **29.2 / 40.0 / 43.3 / 48.3%** |
| Surprise-reply coverage, first 10 / 24 / 96 / 500 (317) | 30.0 / 36.6 / 44.2 / 55.8% | same | **33.8 / 44.8 / 53.9 / 60.3%** |
| Surprise sees-rate, OLD targets, 50k / 300k / 1.5M | 12.0 / 30.6 / 56.8% | 11.7 / 30.0 / 56.8% | **45.1 / 58.7 / 76.3%** |
| Surprise sees-rate, v25 targets, 50k / 300k / 1.5M | 9.1 / 14.5 / 33.8% | 8.8 / 14.8 / 32.5% | **23.7 / 43.2 / 66.9%** |
| Final-blow detection, 50k / 300k / 1.5M (26) | 50.0 / 65.4 / 69.2% | 53.8 / 65.4 / 69.2% | **76.9 / 80.8 / 92.3%** |
| Mean depth reached at 50k / 300k / 1.5M | 3.87 / 4.97 / 5.92 | 3.85 / 4.98 / 5.94 | 3.78 / 4.88 / 5.84 |

Reading:

* **Coverage moves only with the generator.** v24 changed the eval, so its coverage is
  identical to v23's by construction; v25's policy lifts human-find coverage at 24
  candidates from 24% to 40%.
* **The v25-scored targets are harder for every engine** (v23's 1.5M-node rate falls from
  57% to 34%): on average v25's depth-6 judges the replies as worse for the AI than the old
  engines did (mean shift -0.30, |shift| 1.43), so a searched value has to fall further to
  count as seeing the reply. The ranking does not change. Against its own
  targets v25 sees 24 / 43 / 67% vs v23's 9 / 15 / 34%: about 2-3x at every budget. The old
  targets overstated v25's 50k-node gain (45% vs 24%), which is the eval-scale effect the
  re-scoring was meant to remove.
* **v24 is indistinguishable from v23 on these suites** at fixed nodes (within a case or two
  everywhere). Its +50 Elo is self-play strength that these human-game positions do not
  isolate.
* **Final-blow detection is an eval-independent check** (a forced win is a forced win):
  v25 finds 24 of 26 at 1.5M nodes vs 18 for v23 and v24, at slightly lower depth.
