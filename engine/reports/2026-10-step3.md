# Step 3: training-data pipeline v2 (2026-10-06)

Branch `train-s3-data-v2`. Plan section: "Step 3" of `2026-10-training-plan.md`.

## What was built

* **`PyBoard.root_scores_and_play(depth, ...)`**: one fixed-depth search returns every root candidate
  its last iteration completed. For each one it gives the packed actions, `turn_parts`, score, bound
  and stream rank, and then it plays the chosen turn.
  * Only the PV, plus anything that raised alpha, is exact. The other root rows are upper bounds.
  * Universe turns that have no row were not searched; they are not evidence of a bad move.
* **`PyBoard.explore_unemitted`** returns turns from the full enumeration whose result the ordered
  stream, drained to 5,000, never produces. They are drawn round-robin over three groups: dash with
  sacrifice, cast, and other. Each is scored by a depth D-1 search of the position it leads to.
* **`engine/harness/selfplay_v2.py`**: the generator.
  * Seeds come from `$SIGIL_SHARD_OFF`.
  * It writes 10-game chunks atomically.
  * It stops cleanly at `stop_after_s`.
* **`engine/harness/test_selfplay_v2.py`**: checks that the binding is deterministic and that `turn_parts` round-trips.
* **`engine/gcp/launch_s3_fleet.sh`**: launches the Spot fleet.
* **`engine/gcp/pool_s3.py`**: pools the chunks and writes the manifest. It now resumes with `--no-clobber` and retries, has a `--manifest-only` mode, and totals candidates, exploration and the start-kind split.
* **`engine/harness/selfplay_v2_stats.py`**: summary statistics.

## Schema (one npz per 10 games, `v2d<depth>_<shard_off>_<chunk>.npz`)

Per position:

| field | meaning |
|---|---|
| `sfn` | the position |
| `spells` | slot order, `u8[9]` |
| `full` | `f32[132]` |
| `hand` | `i32[13]` |
| `is_red`, `ply` | side to move and ply |
| `game` | game id |
| `kind` | start kind: 0 fresh standard, 1 fresh competitive, 2 human start |
| `start_ply` | ply the game started from |
| `score`, `nodes`, `depth` | the depth-D search's score, node count and depth |
| `chosen` | the played turn, packed `u32[MAX_ACTS]` |
| `n_universe`, `universe_trunc` | size of the ordered universe, drained to 600 |
| `random_played` | whether this ply was a random turn |
| `cand_off`, `n_cand` | slice into the candidate arrays |
| `x_enum`, `x_stream`, `x_missing`, `x_suicide`, `x_trunc` | exploration bookkeeping |
| `y` | winner of the continuation from the side to move; 255 means the 140-ply cap |

Per candidate (`c_*` arrays, sliced by `cand_off`/`n_cand`):

| field | meaning |
|---|---|
| `c_packed` | packed actions |
| `c_parts` | `u16[PRIOR_MAX_PARTS]` |
| `c_score` | score |
| `c_bound` | 0 exact, 1 upper, 2 lower |
| `c_nodes` | nodes spent |
| `c_urank` | stream rank; -1 means not in the stream |
| `c_kind` | 0 root, 1 exploration |
| `c_xclass` | exploration class |

`meta` carries the config JSON (engine `v23+s3@<commit>`, eval `tfit`, adaptive (0.10, 2, 6), width_scale 4, explore 0.10 x 8, random plies 0.08, human_frac 0.5).

Start positions:
* **Human starts (half the games):** filtered human lines `gs://…/data/s3/human_starts_2026-10-06.json`, 1,690 usable games, weighted 4:1 towards turn 20 and later. Games holding Fissure, Rock Slide, Bulwark or a Providence spell are excluded (old rules).
* **Fresh draws (the other half):** a quarter of them competitive. Half draw from all 45 spells (core + Tectonic + Providence), half from the 39 core spells.

## Fleet

* **Machines:** 40 c3d-highcpu-90 Spot VMs (3,600 vCPUs), one shard per vCPU, launched about 08:06 UTC.
  * 8 VMs labelled at depth 5.
  * 32 labelled at depth 4.
  * Each shard stopped at 8,000 s; the watchdog cap was 3 h.
* **Zones:** us-central1-a/b/c/f, europe-west1-b/c/d, us-west2-a/b/c, asia-south1-a/b.
  * Spot VMs draw on PREEMPTIBLE_CPUS (5,000 per region), not the 300-vCPU C3 quota. This was checked on the first VM.
* **Preemptions:** two us-central1-a VMs were preempted at 08:34 UTC. Their shipped chunks are kept, and two replacements ran in asia-south1-b (`sigil-s3-41`, `-42`).
* **Spend:** about 10,300 vCPU-hours, roughly $116 at Spot list prices, measurement run included. All `sigil-s3-*` VMs were deleted and no disks are left.

**Runner issue.** The uploader re-sent every immutable chunk on every 2-minute cycle, then re-sent all of them once more, serially, after the shards finished. That kept 30 VMs up for about 30 minutes past the end of their work.

Fixed in 614d4d66: `runner.sh` now ships an npz only when its size or mtime changed.

## Notes

* The first pooling pass was interrupted twice: once by a DNS failure, once by a local session restart.
  * The final pass verified the pooled prefix chunk by chunk against every run's `data/`, copied the 1,356 missing chunks and wrote the manifest with `--manifest-only`.
  * The Step 4 and Step 5 workers trained on `d4/` and `d5/` while they were still about 98.7% complete.
* `_parts/` under the same prefix holds about 24 GB of duplicate chunks plus per-part manifests from an aborted parallel pooling attempt. Every chunk in it also exists under `d4/` or `d5/`, so it can be deleted. It was left in place pending a decision.
* The labels use eval `tfit`, which was shipped when the run started. The engine now ships `tfit_spell_v2`. The next round of expert iteration (plan 3.6) should regenerate with whatever ships then, and tag it by engine version.
