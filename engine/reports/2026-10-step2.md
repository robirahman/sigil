## Data

The fit uses **`runs/20260831T0045Z`**, 796 shards,
8,208,688 positions from 317,400 self-play games, 7,551,092 with a search score.
Its `cfg`: `eval=tfit depth=4 width_scale=4 adaptive=(0.1, 2, 6) random_ply=0.08`, so
`score` is a depth-4 shipped-shape search in centistones, side-to-move POV (mates
at ±1e7, excluded from score targets). `full` slot order is `SIGIL[p]` order and
`spells` is `board.spells`, also slot order; both index slot p the same way.

* Spell ids in the data are 0-38 only. **No Fissure/Bulwark games to drop** (ids 39,
  41 never appear), and Tectonic/Providence (39-44) are absent too, so those spells
  get no per-spell weight and fall back to the shared `tfit` terms.
* Memory: 6 GB locally, so the fit uses the first 3.0M positions (115k games); the
  rest is unused, not filtered.
* The data was generated by the 2026-08-31 engine; core-spell rules changed since
  only for spells the data does not contain.

## Features (what was fitted, and the one deviation from the plan)

The plan's literal set is `fill x onehot(spell)` and `castable x onehot(spell)`.
`castable` is not free at a leaf (it runs `Board::castable`), so the **shipped** set
is the eval's own per-slot quantities priced per spell:

    stone_p   = mine_p^2 // n_p - theirs_p^2 // n_p      (what sigil_stone sums)
    charged_p = [mine_p == n_p] - [theirs_p == n_p]     (what sigil_charged sums)

The literal plan set was fitted too as a reference (`plan` rows): it is worse
than the shippable one on both metrics, so nothing is lost by the substitution.
Charms sit in one-node sigils where `stone_p == charged_p`, so their two weights
are collinear and are folded into `stone`.

Model: `logit = k * (tfit(pos) + sum_p d_s[spell_p]*stone_p + d_c[spell_p]*charged_p)/100 + b`
with `k, b` the texel scale fitted on `tfit` alone (k = 0.654/stone) and the deltas
L2-regularised towards 0, i.e. towards the shared weights. `tfit(pos)` is
recomputed exactly (integer, truncating) from the stored hand features;
corr(tfit, depth-4 score) = 0.887.

## Shipping

`Weights` gains `spell_sigil: Option<&'static SpellSigil>` (a per-spell-id
`[i32; 45]` pair plus a multiplier). The positional sum adds
`mult * sum_p (stone[spell_p] * stone_p + charged[spell_p] * charged_p)`; `None` for
every existing preset, so `tfit` and all other presets are untouched (default
preset and wasm version unchanged). `unscaled_worst_case` counts the table's
worst legal draw (top three per role, sigils of 5/3/1), so `at_budget` holds.

* `tfit_spell`: ONE 96 cs positional budget, the table 3/4 of it and the `tfit`
  terms 1/4 (`at_budget(FIT_SHAPE + table x3)`). Budget-compliant as the plan asks.
* `tfit_spell2`: `tfit` unchanged at 96 cs plus the table at its own 96 cs
  (192 cs total positional).
* The table is the score fit scaled so its worst case equals `FIT_SHAPE`'s whole
  positional set (1,887 raw).
* Tests: `evaluate_is_exactly_the_dot_product_of_the_hand_features` now covers
  `FIT_AT_BUDGET`, `TFIT_SPELL`, `TFIT_SPELL2` with the per-spell feature vector
  (`spell_sigil_features`, separate from the 15-column `hand_features` so stored
  data keeps its shape); `spell_sigil_presets_hold_their_positional_budgets`.
  `cargo test --release --lib`: 169 passed.
* Native/wasm: the same `eval.rs` code and `weights_by_name` serve both; the wasm
  target builds (`--no-default-features --features wasm`).
* Node rate (`examples/bench.rs`, 76 midgame positions, depth 4, two interleaved
  runs each): tfit 17.6 / 15.7 us/node, tfit_spell 17.6 / 16.8, tfit_spell2
  15.9 / 18.3. Within this Chromebook's run-to-run noise; no measurable cost. The
  fleet arenas confirm it: matched 3.002 s/move and mean depth 6.04 vs 6.07.
* Knob bite (`gcp/smoke_spell_eval.py`, depth 4, 76 positions): tfit_spell picks a
  different turn in 39/76 and a different root score in 53/76; tfit_spell2 28/76
  and 55/76.

## Cost

Six c3d-highcpu-90 on-demand VMs in us-east1 (us-west1 has no C3D quota in this
project: `CPUS-PER-VM-FAMILY-per-project-region` limit 0): about 2.3 VM-hours at
3 s and 5.1 at 10 s, so ~7.4 VM-hours x ~$3.2 = **~$24**. Fit and smoke tests ran
locally. All six VMs deleted; `gcloud compute instances list` shows no `sigil-s2-*`.

## Recommendation

**Ship `tfit_spell`** as the next default eval candidate: it passes every gate
in the plan (offline on both targets and all spell folds, +59 at 3 s, +50 at 10 s,
no node-rate cost) and, unlike `tfit_spell2`, stays inside the 96 cs budget while
scoring at least as well. Shipping means a default-preset change plus the usual wasm
rebuild / version bump / `wasm-smoke.js`, which this branch deliberately does not do.

Then **refit on step-3 data**: the table is zero for Fissure, Rock Slide, Bulwark
and the three Providence bank spells (ids 39-44), and it was fitted on 3.0M of the
8.2M positions available. The per-spell term carried more outcome signal offline
than all of `tfit`'s shared positional terms, so the budget split (3/4 to the
table) is worth one more arena (e.g. 1/2 and 7/8) once the refit exists.
